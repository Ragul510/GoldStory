# The Gold Story: React (JavaScript) + Node.js

Personalized 22K / 24K gold jewellery.

```
web/   React 19 + Vite, plain JavaScript (JSX) + React Router      dev: http://localhost:5173
api/   Node.js + Express + SQLite (built-in node:sqlite)           http://localhost:4000
API.md every backend route, with examples
```
Needs **Node 22.13 or newer**.

## 1. Start the backend with dummy data
```bash
cd api
cp .env.example .env          # set ADMIN_PASSCODE (8+ chars) and JWT_SECRET
npm install
npm run seed                  # dummy products, orders, customers and demo rates (npm run seed:reset starts over)
npm start                     # http://localhost:4000
```

## 2. Start the frontend (connected to the backend)
```bash
cd web
npm install
npm run dev                   # http://localhost:5173   (admin: /admin, log in with your ADMIN_PASSCODE)
```
Vite forwards `/api` and `/uploads` to the backend (see `web/vite.config.js`), so the two are connected with no extra setup.
If the backend is off, the site shows built-in dummy products and a red "Demo data" banner (`VITE_DEMO_FALLBACK=true` in `web/.env`; use `false` in production).

## How the frontend and backend are connected
- **`web/src/services/api.js`** is the single file that calls the backend. Every route in `API.md` has a function there
  (`getProducts`, `getQuote`, `createOrder`, `adminLogin`, `adminSaveProduct`, ...). Components never call `fetch` themselves.
- Public screens: `pages/Home.jsx` (products from `GET /api/products`), `components/Studio.jsx` (quote, artwork upload, order).
- Admin screens: `components/admin/AdminApp.jsx` and `ProductForm.jsx` (login, products with up to 8 images and a 360 video, status, orders, customers, rates, passcode).
- Same-origin cookies: in development through the Vite proxy, in production because the Node server serves the built site and the API together.

## Tests
```bash
cd api && npm test                         # 22 backend checks (temporary database)
cd web && npm test                         # 6 screen render checks
cd web && npm run test:connection          # 13 checks: the React API layer against the RUNNING backend with dummy data
```

## Run as one server (production style)
```bash
cd web && cp .env.example .env && npm run build        # set VITE_SITE_URL to your real URL first
cd ../api && NODE_ENV=production npm start             # serves the site AND the API on port 4000
```
In `api/.env` set `NODE_ENV=production`, `JWT_SECRET`, `ALLOWED_ORIGINS=https://yourdomain.com`, `SITE_URL=https://yourdomain.com`.
Use HTTPS (Nginx/Caddy) and keep `DATA_DIR` on a disk you back up.

## SEO note (React single-page app)
Done: static title/description/Open Graph in `index.html`, per-page titles and canonical links, product list as JSON-LD, `sitemap.xml` and `robots.txt` generated by the API, `/admin` noindex, cacheable build.
Limit: content is drawn by JavaScript. Google copes, but a pre-rendered or server-rendered site (Next.js) is more reliable for rankings and link previews.
